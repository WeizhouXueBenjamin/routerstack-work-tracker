# 当前产品要求

- 保存的 XLSX 是实际工作、Invoice、金额与确认余额的来源。每项工作独立 Invoice，同日允许多项，ID 可后补。
- 数据完整性优先；中文操作界面，英文技术字段。保留离线 HTML/JS/JSZip，运行不需要 Node.js 或互联网。
- Estimated、Extra、App、银行到账、确认结转分开。App 空白为待填，0 为明确金额。差额不是已核实欠款。
- 本轮确认：AH 每日 18:00–06:00、1.5 倍、最低 2h；Lunch 数字小时，空白按 0，先扣普通时段；最低补足按扣休息后的普通/AH 占比。
- Tool 与 Excel 可先后编辑原始字段和 Config；公式及列结构固定。Config 变更预览整周期差异，再另存新版本。
- 旧 2.0 文件先只读；用户确认逐笔升级差异后另存 3.0。旧文件保持不变，不批量迁移历史。
- 保存区分表单/结转草稿、记录修订、导出和下载确认。默认另存，不能把发起下载称为已可靠保存；会话中的原文件保护不能因重开其他文件而清除。
- 结转仅带明确选择的 Invoice 确认余额，允许部分余额与空白周期；不当成本期新工作，不推断逐笔支付状态。
- 月度视图仅统计当前 XLSX 的 Job 日期，结转独立列示；月度合计不随搜索或提醒筛选变化。文件总览也将工作预计与确认结转分开；空白 App 不参加比较，无可比项则不展示为零。
- 提醒包括金额差异、Invoice 待补、App 待填，不产生付款状态。筛选只影响查看和明确选择的清单范围，保存始终包含全部记录。
- Tim 清单默认含所选月份的差额/待补项与本文件确认结转；允许改为当前可见或所选月份全部工作。清单标明范围、原始估算依据及未保存状态，不自动发送。
- 轻量结算证据台账仍待后续确定，不增加跨文件月度合并或银行分摊。

完整字段与版本契约见 [architecture.md](architecture.md)。
