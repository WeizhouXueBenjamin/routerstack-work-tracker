# 2026-11-07 交接摘要（历史）

原 RouterStack_Codex_Repo_Docs_Only/ 的六份重复材料合并于此。它们描述 v0.2.0 baseline，后来规则、实现和范围均有演进；不再保留可直接执行的旧 Prompt。当前要求见 [Project Goal](../PROJECT_GOAL.md)，旧格式细节见 [architecture-v3.md](architecture-v3.md)。

## 原始痛点与已否决方案

- 手工插 Excel 行、复制公式和汇总容易漏工作；RouterStack App 可能漏工时/AH/Extra，用户通常只知银行到账总额，向 Tim 核实后才可能取得部分 Invoice 依据。
- 确定 Tool 是真正的离线 HTML 小程序；XLSX 的 Tool Sheet 只是说明/汇总。Work Log 与 Config 共同保存在同一 XLSX，不维护两套工作事实。
- 一工作一 Invoice，同日可多项，Invoice 可后补；保留原始时间/费率和精确工时，合并展示 Billable (AH)。
- 否决 Lunch 勾选/下拉和超过 8h 自动扣 1h；使用数字小时。
- 否决日常逐笔 Paid/Unpaid、繁琐 Void/Reissue、为升级批量迁移完整旧工作、云同步或不必要的框架/后台。
- 当时只允许人工选择确认余额结转；现已演进为保留未解决问题、自动提醒及必要来源，不能恢复“只有余额能带入”的旧限制。

## 历史技术状态与纠正

- 当时最低 2h、18:00 AH、1.5×、Lunch 普通优先被列为暂用假设；后续用户选择估算模型及 06:00 AH 结束见[决策演进](decision-history.md)，不等于官方全部政策。
- v0.2.0 交接记录仅有 6 项基础检查和既往手工浏览器往返，不保证后续版本或边界。
- 旧审查曾关注固定 sheet2/sheet3 XML 路径、表头验证不足、下载即清 dirty、结转混入收入、公式缓存与容量/版本等风险；不能据此宣称当前仍有这些缺陷，应核对实际源码。
- 早期“部分行硬编码”的判断有误，原表使用 shared formulas；读取必须识别共享公式。
- 私人会话、真实 Invoice/历史日期/工资/银行记录不属于本摘要，不能为复原交接而提交真实数据。
