# Project Goal 与产品要求

更新：2026-11-16。依据：用户《Documentation Alignment & Project Scope Reset》。本文为唯一当前产品范围依据，已合并原目标稿与产品要求；2026-11-16 用户已明确授权最终修正版的 P0/P1 实施；该授权限于记住周期、快速录入与轻量核对。

## 目标与工作流程

三个目标：**少填重复信息；独立估算并发现 App 金额差异；跨周期不丢未解决事项**。质量顺序为数据完整性、Excel 兼容性、录入便利、样式。本项目是个人轻量工具，不承担会计、工资核算或完整银行对账职责。

1. 打开最新保留的周期 XLSX，逐项记录实际日期、Start/End、Lunch、Rate；连续录入尽量复用日期和已配置默认费率。
2. 后补 Invoice、App、Extra、Notes；查看差额/缺资料提醒，需要时复制清单向 Tim 核实，不自动发送。
3. 银行到账只记日期、金额和可选备注；用户往往仅知总额，不能推断具体 Invoice 已付或未付。
4. 按实际核实结果人工记录未解决问题或确认余额；未确认差异仍是问题，金额可未知。
5. 显式保存并确认保留旧周期后，手动创建新文件，延续未解决事项及必要来源；旧文件归档，新 Work Log 干净。

以上是目标流程；完成与缺口见[路线图](roadmap.md)。

## 必须保持的行为

- 用户保存的 XLSX 是工作、日期、Invoice、实际费率、到账与确认事项的唯一持久依据；内存不是第二份账本，未知事实不编造。一项工作一张 Invoice，同日可多项，Invoice 可后补且保持唯一。
- 计算所需为有效 Date、Start/End、实际 Rate。Lunch 为数字小时，新工作空白按 0 并保留空白；不自动扣餐、不恢复勾选框。展示 Billable (AH)，精确数值及原始字段不丢失。
- Estimated、App Displayed、银行实收、人工确认结转是四种独立量。已知 Extra 独立保留；Expected Total = Estimated Work Revenue + known Extra，App Difference = Expected Total − App Displayed。历史 Estimated Net Revenue 名称不保证税后实收。
- App 空白为未知，0 为明确金额；差额和缺 Invoice/App 提醒从当前数据自动派生。App 更正更新当前差额并留必要来源，不能证明银行已付或关闭无关问题。
- 银行记录单独展示，不要求 Batch/Invoice 归属，不按日期/金额匹配，不自动计算债务或单项付款状态。
- 人工确认余额须有明确金额、来源及必要说明；问题、提醒、银行款和余额不简单相加成“欠款总额”。
- 周期由用户手动切换，不绑定自然月或到账日期。携带未解决事项所需的来源周期、记录身份、已知 Invoice、原始工作、规则/金额和说明；不盲目复制全部历史、不把历史收入重计为新收入。
- 月度按当前文件 Job 的工作日期统计，历史/确认结转单列；筛选不缩小整月合计或完整导出。无可比 App 显示未知。Tim 清单标明范围、估算依据和保存状态。
- 分清表单未提交、内存修改、导出快照与下载待确认；显式保存前不称已持久化，失败/取消保留草稿，旧快照确认不清新修改。Tool 和 Excel 先后编辑，Config 变更不静默重算历史已确认金额。

## 架构与兼容边界

| 层 | 职责 |
|---|---|
| Tool | 快速交互、差异提醒、轻量核对、显式保存、手动换期 |
| Work Log | XLSX 中的持久工作事实与必要来源 |
| Config | 用户可配置的计算规则、默认录入参数及版本 |

三层不要求恰好三张 Sheet；当前 schema 4.1 六张 Sheet、旧 2.0/3.0/4.0 读取、全部列/表/关系契约均保留，见 [architecture.md](architecture.md)。保持离线 HTML/JS/JSZip，不新增 API、追踪、云存储、自动上传或运行时联网依赖，真实财务数据不入仓库。

现有代码含批次、付款分配、余额派生、Pending/Site 和审计，旧 4.0 换期携带未获批次核对覆盖的完整工作；4.1 已按明确范围选择性携带必要来源。它们是兼容事实，不代表继续扩建的要求；本轮保留兼容模块和数据，4.1 结转按用户明确类别及独立事项选择，不扩建旧财务流程。未来精简须先明确兼容影响、保全历史数据和必要测试。

## 下一方向、暂缓与排除

**本轮授权范围**：安全重开最近周期、Save / Save As、轻量 App 核对与选择性结转、可配置默认费率、连续添加保留 Work Date/恢复默认费率/清空专属字段、键盘重复录入、清楚的保存状态。细节与验收只维护在[路线图](roadmap.md)。

**暂缓，未经另行批准不激活**：Site 录入/自动补全/预设、费率预设、复杂 Pending Entries、复制工作、多行网格/批量及额外输入模式、额外图表和非必要样式。已有字段与资料继续兼容。

**排除出默认开发范围**：Settlement Batch 工作流、Invoice 付款分配/部分付款管理、自动银行匹配、自动债务计算、Paid/Unpaid 管理、复杂税费/扣款/报销/会计模块、附件库/嵌入、银行或 App 接口、OCR、云同步、自动多文件合并、框架重写。这些不能挂成“以后自动做”的待办。

## 确认与假设

- 本轮用户确认：三个目标、轻量核对、快录优先及上述范围边界。旧推荐/问卷和通过的测试不构成新功能授权。
- 历史[决策记录](archive/decision-history.md)载明用户选择最低 2h、AH 18:00–06:00、1.5×、Lunch 普通优先、最低补足按比例的估算模型；代码/测试只验证实现，不证明 RouterStack 官方全部政策，本次不改模型。
- 真实默认时薪、特殊计价、夏令时/节假日、税费/报销及银行口径仍须实际依据，不能从旧记录或总额猜测。
- 最近文件采用仅存句柄与最小元数据的 IndexedDB 便利引用；成功录入聚焦 Start，保留日期、恢复 Config 默认 Rate。用户主动重开并按浏览器权限授权，不承诺静默打开或自动保存。

新功能提案必须说明服务哪个核心目标、现有功能为何不足、增加多少输入或维护负担。
