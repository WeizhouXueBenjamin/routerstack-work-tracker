# Project Goal 与业务边界

本文件定义当前产品目标与范围；字段、计算、文件格式和保存机制以 [architecture.md](architecture.md) 为准，使用与命令见 [README.md](../README.md)，开发约束见 [AGENTS.md](../AGENTS.md)。

## 核心目标

1. 少填重复信息，便于连续记录真实工作及后补 Invoice／App 等资料。
2. 独立估算工作收入，发现与 App 显示金额的差异，保留可核对的事实。
3. 跨周期保留明确选择的未解决事项、确认余额及必要来源，不丢失上下文。

质量顺序：**数据完整性 > 可预测的 Excel 兼容性 > 录入便利 > 样式**。

这是个人工作与收入核对工具，不是 RouterStack 官方软件，不承担会计、工资核算或完整银行对账职责。

## 产品职责

- **Tool**：唯一业务编辑入口，负责录入、核对、规则预览、显式保存与结转。
- **Work Log**：展示真实工作和收入比较，区分 Current 与 Historical；筛选只影响查看。
- **Config**：保存用户可编辑的估算规则和可空默认费率。
- **XLSX**：唯一持久工作事实来源；每个周期独立文件，由用户保留和备份。

一个工作对应一张唯一 Invoice，同日允许多项工作，Invoice 可后补。不编造工作、日期、费率、Invoice 或付款。具体校验与未知值语义在数据契约中定义。

## 金额与核对边界

Estimated、App Displayed、银行实收和人工确认余额分开处理：

- 估算及差额用于核对，不自动确认债务或付款。
- App 未知与明确 0 分开；银行总额不能推断某项 Invoice 已付。
- 人工事项与确认余额可独立存在，也可关联真实工作；不为关联而生成虚构 WorkRecord。
- 银行登记保持日期、正数金额和可选备注的轻量职责，不扩建付款分配流程。
- 收入 Summary 不混入银行实收、人工参考金额或确认余额。

既有估算模型不代表官方政策。未知规则与真实费率不能靠文档或测试猜测。

## 当前交互范围

仅面向桌面，验收视口为 **1366×768、1920×1080**。保留左侧紧凑录入、右侧 Revenue Summary／八列 Work Log、Compact／Expanded 视图及 Config／Bank Received／Unresolved 互斥抽屉。

视图切换、关闭抽屉和键盘操作必须保护草稿及编辑上下文；保存状态与错误须明确。应用保持离线优先，不依赖账号、后端或运行时联网。

## 范围外与后续提案

不恢复旧 Settlement Batch、付款分配、Payable、金融证据库、通用审计／回放、Pending／Opening 兼容模型、Tim 报告或 Excel 外部业务修改接受流程。

暂缓 Site 录入、费率预设、复杂待补流程、多行网格／批量录入、复制工作、额外图表／报告、附件库、银行／App 接口、OCR、云同步、多文件自动合并、移动适配和框架重写。此列表不是开发授权。

新功能提案必须回答：

1. 服务哪个核心目标？
2. 现有功能为何不足？
3. 增加多少输入或维护负担？

应用版本调整、文档整理和工程清理均不授权改变数据格式、计费规则或既有业务行为。后续工作方向见 [roadmap.md](roadmap.md)。
